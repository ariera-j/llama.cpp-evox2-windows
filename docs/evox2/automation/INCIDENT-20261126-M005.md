### 稼働時間に関する運用者の観察

経験上、原因不明のフリーズは電源投入から数時間以内に多く、数日間稼働したままの長時間計測では比較的少ない。今回の最終 RAM サンプルは OS 起動の約3時間30分14秒後。障害率と稼働時間の関係を判断するための母数は得られていない。

Kernel-General 12/13、User32 1074 等で確認した OS 停止期間は、11/15 約7時間27分、11/17 約20時間34分、11/19 約17時間31分、11/20 約19時間53分、11/21 約10時間53分、11/22 約18時間12分、11/23 約8時間19分、11/25 約10時間44分。これらは OS の停止区間であり、物理電源 OFF の実測はない。11/21 の GPU タイムアウトと手動再起動は Gemma 4 の RGP 実験中に発生した。当時のパッチ、RGP マーカー、一時停止機能との関係は未確認で、追加ダンプ解析は今回の対象外。

## 復旧確認・再開条件

復旧後の SSH から、推論／ADLX／ビルド実行ファイルの残留を確認した範囲では該当なし。復旧前の PID 14780 は終了済み。初回確認では物理 RAM 空き 24.660 GiB、コミット 8.648／127.647 GiB、WDDM アダプター Dedicated 使用量は合計約0.526 GiB、P-MODE は `Performance`。Stage 2 の既存 llama-bench SHA-256 は `576cda5ac89f2eb0b534b25ff37da78dfdc14c28e7b7d1ab5bb56f9ed7cdc8d2` と照合した。

元の M001～M005 子ログ、Matrix 部分結果、親ログは実機の別ディレクトリ `incident-M005-preserved-20261126-014720-524` に複製し、78ファイルの SHA-256 を原本と照合した。元の Matrix run CSV には正常4件のみ、M005 の有効速度データはない。元の計測を参照する手順は [作業3-4記録](BENCHMARK-MATRIX-ROUNDS-B12651.md) を参照。

`evox2-runner` の SSH から `Get-WinEvent` と `wevtutil qe` がいずれも System と Application をアクセス拒否とした。このセッションでは、run ごとの新規重大イベントの有無を判定できない。無人の復旧後計測は開始前に停止した。再開時は既存の許可範囲で重大イベントを確認できる実行経路を確保し、ThinkPad 側から一意の識別子で1件ずつ起動する。独立した複数 run を実機側へまとめて委任しない。各 run の終了・有効な JSON・プロセス終了・RAM／コミット／GPU メモリの回復・P-MODE を確認し、重大イベントまたは SSH 切断があれば後続 run を起動しない。

Adrenalin 26.8.1 を維持する。SSD への大量書き込みは現環境で観測されておらず、今回のアクセス違反とは別事象として扱う。Adrenalin 26.11.2 と ROCm 10.2 の試用は作業3-5および作業4の後の独立候補とし、安定性問題が続く場合は優先度を再評価する。
