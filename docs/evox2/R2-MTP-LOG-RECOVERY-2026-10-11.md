## How this affects the current r5 MTP evaluation

- The r2 results establish **compatibility and historical MTP ON TG gain at 64k/128k with a PP penalty**, **not** the performance of current pinned-upstream r5. r4 has newer upstream-native MTP and measured other overheads; see [r4 native/dense fix and baseline](R4-COMMON002-UPSTREAM-REVIEW-2026-10-04.md), [initial 28-run backend matrix](R4-COMMON002-OVERNIGHT-ANALYSIS-2026-10-04.md), [256k dense indexer abba](R4-COMMON002-DENSE-INDEXER-ABBA-VALIDATION-2026-10-04.md) and [target no-op abba](R4-COMMON002-QSA-NOOP-ABBA-VALIDATION-2026-10-04.md).
- Do **not** start with an r5 128k/256k benchmark or copy the r2 experimental MTP-QSA prototype. First attempt the **existing r5 binary + same self-contained Q8_0 sidecar** in a short allocation/generation smoke; r5 pinned `src/models/qwen4exp.cpp::graph_mtp` lacks the **ratio-zero k-pool-input guard** which r4 needed for this historical GGUF. A `GGML_ASSERT(buffer)` on first decode is a credible predicted failure, **not** an observed r5 failure until logged.
- First smoke: **MTP OFF** short to prove the chosen binary and model, then **MTP ON** short with `DraftMax=2, DraftPMin=0, f16 main+draft K/V`; inspect status/exit, main/draft metadata, loaded layer ratio0, actual drafted/accepted counts and any buffer assert. If ON fails, port *only* the minimal guard equivalent to [Unsloth #240](https://github.com/unslothai/llama.cpp/pull/240) / r4 and rebuild in a **separate isolated test branch**; do **not** port r4 MTP optimization candidates until a clean baseline is established.
- After a working smoke: 32k *greedy* OFF/ON fixed 128-token smoke for output/rollback, then 64k real input with **fixed** `-n 512 --seed 1234 --ignore-eos` and 64k ON/OFF/ON/OFF or ABBA. Use `-c 65536, -b 2048, -ub 1024, -ctk/v f16, -md Q8_0, DraftMax=2, temp0.2/topP0.8, MTP-diagnostics OFF`. Fix Vulkan union state explicitly (ON or OFF) **within** the pair. Report PP, TG, prompt time, gen time, total, accepted/drafted, per-run response identity, binary+DLL SHA and model/input hashes. **Do not call this a same-source A/B versus r2**: r2 lacked fixed-length/seed and 64k had Vulkan PERF_LOGGER ON.
