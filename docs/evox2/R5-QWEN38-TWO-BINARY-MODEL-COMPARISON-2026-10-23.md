# Qwen3.8-Flash-Next: 2種類のVulkanバイナリでのモデル比較（2026-10-23）

> **結論と集計方法**：10/22〜23のABBA実測のうち、PP/VRAMクロックが回復した高速状態の**計28run**（7条件×モデル2種×2回）を主比較とし、異常再起動後の低クロック状態8run、中断前に完走した128k 2run、単発トラブルシューティングは**参考扱い**に分離。平均は同一条件・同一モデルの2runの算術平均。PP/TGの単位はtok/s。これらは新しい計測結果ではなく、利用者から提出されたZIPを再集計したもの。

## 条件・比較上の注意

- マシン：GMKtec EVO-X2、Ryzen AI Max+ 395 / Radeon 8060S、Windows、UMA 96GB、Vulkan、P-MODE Performance、ADLX併用。
- モデル：Agention `Qwen3.8-Flash-Next-ROCmFP4-FAST-v2-ple16.gguf` vs Unsloth `Qwen3.8-Flash-Next-UD-IQ3_XXS-ple16.gguf`。本体GGUFサイズは各約87.1GiB / 76.3GiB。
- Stage5：`build-vulkan-rocmfpx-stage5`、**b11561 / bddcbf2f1**、MTP OFF。実行ファイルSHA256 `7b35f6547ae667156bdb47d6e716886000ff99092619c6496fbae622bdba17f7`。r5統合版のQSA union/DENSE/NOOPは使用していない。
- r5統合版：`build-vulkan-r5-noop-rocmfpx`、**b11588 / 1c3167fb6**、QSA union ON、MTP DENSE/NOOP有効。実行ファイルSHA256 `a816c4e8bf68e923d662f2e470f06b892bd9d8c6c2b0305cc2d26ad597f0c1d5`。MTP OFF時はドラフトなし。
- MTP ON時のドラフトは**ROCmFP4用ROCmFP4 FAST**（約2.28GiB）と**Unsloth用Q8_0**（約3.85GiB）を各ターゲットに対応付け、`DraftMax=2, DraftPMin=0`。これは**ターゲット＋別々のドラフトのシステム比較**であり、ターゲット量子化だけを比較したものではない。
- 共通設定：入力29,557/61,789/126,253 tokens、Context 32k/64k/128k、出力最大512、温度0、reasoning off、KV f16、`-ngl 999 -ncmoe 0 -t 4 -tb 4 -b 2048 -ub 1024 --fa auto`。3入力は同じANLP文書の長さ違いで独立した3ドメインではない。
- **測定の欠損**：b11561のMTP ONはなし。b11588の64k/128k MTP OFFはなし。64k/128kのバイナリ間の速度差をコード改良率やMTP単独効果と解釈しない。

**主要所見：**

1. **MTP OFF（ターゲット単体）ではROCmFP4のPPが優位**：b11561の32/64/128kで +3.53% / +1.91% / +1.23%。b11588の32k MTP OFFでも +3.45%。TGはほぼ同等。
2. **b11588 MTP ONではROCmFP4＋対応ドラフトのTGが優位**：Unsloth＋対応ドラフトに対し32k +9.55%、64k +3.38%、128k +4.00%。PPは32/64kではROCmFP4が+2〜3%、128kでは-0.18%でほぼ同等。
3. **b11588の32k MTP ON/OFFの参考比較**：ROCmFP4 PP 422.08→398.76（-5.52%）、TG 27.18→36.59（+34.62%）。Unsloth PP 408.01→387.99（-4.91%）、TG 27.28→33.40（+22.43%）。ただしONは10/22 16:50台、OFFは10/23 00:32台で、間にOS再起動・クロック状態変化・P-MODE操作があったため、**交互実験による厳密なMTPコスト推定ではない**。
4. **128kのPP優劣は結論保留**：b11588 MTP ONのROCmFP4が1run目300.98→4run目293.51（-2.48%）に低下。PP中VRAM平均約918.5→905.0MHz、GPU温度約76.2→78.5℃。Unslothは298.32→297.27（-0.35%）。PP・クロックの相関はあるが、因果・熱保護状態の発動は証明できない。
5. **32kは安定**：b11588 MTP OFFの反復差はROCmFP4 0.13%、Unsloth 0.24%。128kの時間依存変動を短文の結果に無理に一般化しない。

反復runの出力fingerprintは各条件のモデル内で一致することを確認。b11561 MTP OFFではUnsloth 32k/128kが479/481tokensで自然終了し、ROCmFP4は512tokens上限まで生成（64kは両者512）。b11588 MTP ONの64kではUnsloth 511tokens、ほかは512。出力長の差は品質優劣の証拠ではない。ANLP要約では固有名詞を多く挙げるROCmFP4側と、分類・抽象化傾向のUnsloth側という探索的な違いはあったが、同じ文書系列の観察であり、精度・ハルシネーション・量子化固有差の結論にはできない。

- 先行調査： [R5-ROCMFP4-VS-UNSLOTH-SAME-BINARY-2026-10-22.md](R5-ROCMFP4-VS-UNSLOTH-SAME-BINARY-2026-10-22.md) および [R5-NOOP-ROCMFPX-INTEGRATION-CHECK-2026-10-21.md](R5-NOOP-ROCMFPX-INTEGRATION-CHECK-2026-10-21.md)。
- **データ解釈上の境界**：バイナリ比較・MTP効果・モデル量子化差・ドラフト形式差・GPU動作状態が同時に違う条件を混同しない。特にb11561 MTP OFFの64k/128kとb11588 MTP ONを直接コード高速化の倍率に換算しない。
- **現時点で比較完了とする**。必要なときだけ、32kでの同一モデルON/OFF交互ABBA、またはb11588の64k/128k MTP OFFの欠損補完を検討。OS全体のハングも発生しているので、単に平均値を増やす目的で長時間の再計測を繰り返さない。
