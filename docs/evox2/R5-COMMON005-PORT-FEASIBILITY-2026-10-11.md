Retain the same compact selected-K/V decode principle, but adapt the selection/mask boundary for r5's k-pool graph before any code port.** Since the next likely MTP research generally processes speculative verification in multi-token ubatches, the historical *single-token-only* gather is not a prerequisite. **Defer independent implementation until a non-MTP ROCm long-context decode study, another research dependency, or the first integration candidate selection.**

## What r3 actually proved (not r5 measurements)

COMMON-005 compressed physically selected K/V cache rows (and the original mask rows) using `ggml_get_rows`, reshaped them and performed normal FA, restricted to `cparams.flash_attn && n_tokens == 1 && top_k shape [width,1,1,1] && n_kv >= 4*width`. `QWEN4EXP_QSA_GATHER=0/1` allowed same-binary A/B; unset defaulted **enabled in r3**.

- ROCm PP effectively unchanged. 64k TG **20.55 → 22.60**, 128k **16.425 → 20.41**, 256k **11.68 → 17.37 tok/s**, or **+10.0% / +24.3% / +48.7%**; latter two ABBA. RGP showed compact FA `flash_attn_tile<256,256,2,1,false>` **~41.93 μs at 128k** instead of full-cache `flash_attn_tile<256,256,1,4,false>` **~1.452 ms**; 256k compact FA ~42 µs was estimated in summary, while dedicated ROCm validation notes show selected events/limitations. Existing `k_get_rows_float` indexer expansion remained ~0.448 ms (128k) / ~0.907 ms (256k), so selection still had depth cost.
- Vulkan under r3 saw **−2.0% / −2.0% / +2.6%** TG at 64/128/256k, respectively. This was never a universal backend default recommendation.
- The valid baseline and correctness are **r3+COMMON-004+PLE16**, f16 KV, MTP disabled, mostly `llama-cli` real prompts with 1024 generation budget. r5 upstream and driver/toolchain changes prevent copying the speedup percentages as predictions or comparing absolute values as source-only A/B.

## Why cherry-picking r3's 71 lines is not a correct r5 port

| Contract | r3 COMMON-005 | r5 pinned source | Port implication |
| --- | --- | --- | --- |
| Selected data | `build_qsa_top_k()` returns **per-cell top_k ids**, [width, n_tps, 1, n_stream], valid as cache gather indices for eligible single-token path | `build_qsa_sel()` returns **full-KV additive mask `sel`** plus `selected_rows`, with `n_sel` from k-pool sizes; full `top_k` is **pooled-block IDs**, not cache-cell IDs | Old `top_k->ne[0]` and direct gather cannot be transferred. New interface/locally derived safe indices required |
| Handling inactive selection | r3 top_k selects real KV cells; original causal `kq_mask` rows gathered directly | `pool_idxs` + incomplete `tail_idxs` include **`n_kv` sentinel**, and scores can pick invisible pools. r5 maps each dead slot to a separate **dump row `>= n_kv`** so `ggml_set_rows` has no conflicting writes | `selected_rows` **must not** be passed directly to `ggml_get_rows` on the actual full K/V cache. Out-of-range rows need safe substitute indices AND a guaranteed `-inf` compact mask |
| Visibility and mask | Uses `inp->get_kq_mask()` gathered at valid selected ids; selection from per-cell scored top-k | Builds `sel = ggml_set_rows(mask_all, zeros, selected_rows)`, reshapes to `n_kv` and adds `kq_mask`. `live_pool`, `live_tail` and dump remap enforce incomplete/foreign/causal visibility | Safe compact mask must combine the **original attention mask** with the **current k-pool live/invalid slot semantics**. A clipped dead index could point at a visible cell; gathering the mask at that index alone is **incorrect** |
| Graph/FA API | `build_attn_qsa(..., top_k, kq_scale, il)` then compact `build_attn_mha(..., 0, kq_scale, il)` | `build_attn_qsa(..., sel, selected_rows, n_sel, kq_scale, il)` then `build_attn_mha(..., n_sel, kq_scale, il, selected_rows)` | r3 inserted text may fit local hunk context but **cannot compile or preserve semantics** as-is. On compact K/V, do **not** pass the old full-KV `selected_rows` hint or set `n_kv_max=n_sel` without a reason: original selected-row ids refer to full KV |
| Work avoided | Bypasses r3 full attention mask construction inside `build_attn_qsa`; indexer top-k still computes earlier | r5 `build_qsa_sel` **always** constructs full-length selection mask before `build_attn_qsa`, then uses it as the backend FA input | A one-function insertion may still do full-length mask-scatter work in decode. For maximum gain, split the selection output from full-length mask building **at graph construction time**, preserving a fallback and the r5 k-pool graph reserve invariants |
| Backend coverage | r3 f16 K/V ROCm long-context decode improvement; Vulkan sparse backend close to same perf | r5 ROCm HIP compact sparse path excluded by `GGML_USE_HIP`; Vulkan union/sparse already has alternative selection modes | Target ROCm first; Vulkan only separately when a benchmark warrants it |

**Subtle but important:** r5 `ggml_flash_attn_ext_set_selected_rows` stores `selected_rows` as a hint in **FA src[5]**, not an allocation of compact K/V by itself. It is therefore **not** the same guarantee as r3 `ggml_get_rows(K/V, top_k)`. The existing r5 code still passes the **full** `mctx_cur->get_k/v` tensors to FA.

## Reuse vs redesign estimate (source-only, no build proof)

**Keep:** r3's bounded-single-token decode gate; cell-row reinterpretation of K/V; `ggml_get_rows` to create physically compact K/V; reuse of the original causal/sequence constraints; `build_attn_mha` with **compact** tensors; opt-in reversible same-binary control.

**Adapt:** expose `safe_selected_cell_ids` and `live_slot_mask` from the current `build_qsa_sel` (or construct equivalents there); ensure all gathered indices lie in `[0,n_kv)`; preserve `-inf` for every dead/invisible pool/tail slot even if its safe substitute row is visible; build contiguous F16 compact attention mask and maintain causal/sequence restrictions; validate shape/stride/quantized KV requirements; avoid reintroducing a full-length `sel` dependency on gather-eligible graphs if measuring true graph cost.

**Preserve:** r5 k-pool pooled-key lifecycle and `new_pool_rep` stable graph inputs per upstream #29958, short-context fallback, all prefill/multitoken/speculative/MTP verification fallback, and Vulkan's native sparse/union paths. **Do not restore r3 `build_qsa_top_k` or replace the newer upstream pooling implementation.**

**Difficulty classification:** **algorithmic approach largely reusable; text patch nonportable, needs a focused r5 model-graph adaptation, not a new HIP kernel.** The minimum *correct* port is likely broader than one method because safe gather IDs/liveness are produced before `build_attn_qsa`. Eliminating redundant full-mask graph work and preserving graph-reuse contracts increase scope. Actual feasibility and cost can only be proven by code + correctness tests. Avoid promising “71 lines, drop-in”.

### MTP relationship and next-project gate

The old path requires `n_tokens == 1`, so it does **not** normally apply to MTP speculative verification, which consumes more than one token. [Upstream #28213 MTP discussion](https://github.com/ggml-org/llama.cpp/pull/28213#issuecomment-5546512474) independently reports that the old gather gate did nothing on an Unsloth MTP speculative workload. An extension to batched speculative attention would be a **separate design, different mask-per-token and KV alignment problem**, and **not covered by r3 validation**.

Therefore under the [research/integration policy](INTEGRATION-POLICY.md):

1. **Do not begin COMMON-005 just because r3 once verified a +48.7% ROCm TG improvement.** It is not part of the completed FA **prefill** question, nor a prerequisite for a forthcoming **MTP-on** study.
2. **Park COMMON-005 as a validated-r3 / adaptation-required-r5 candidate** until a focused non-MTP ROCm deep decode question or first integrated-snapshot patch review. This is a scheduling decision, not a claim that its gain disappeared. If the next selected topic needs multi-token MTP optimization, reassess relevance explicitly rather than silently enabling a single-token patch.
3. When revisited, preserve same-binary `QWEN4EXP_QSA_GATHER=0/1` (prefer initial **default OFF** as an experimental port until r5 ROCm correctness/PP/TG gates pass), model PLE16 f16 KV, no MTP first, and raw benchmark identities. Test backend ops, short allocation/greedy/synthetic missing tail, 64k smoke then 128k/256k ABBA ROCm TG, full-length vs gathered masks/equivalence, fallback compatibility and repeated cache/reuse/seq operations. Port Vulkan only after separate performance gates.

No implementation has been attempted, no source or performance baseline was modified, and no upstream pin was moved.
