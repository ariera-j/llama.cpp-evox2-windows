## 1. 背景と目的

- [旧5モデルの論文要約／検索比較](https://github.com/ariera-j/evox2-llm-experiments/tree/main/benchmarks/search-retrieval)に**モデル条件を2つ追加**したい。
- 追加①：初期にQwen3.8 Flash Nextを試した時の**Unsloth UD-IQ1_S**がローカルに残っている。当時はUD-IQ3_XXSが正常動作すると判明して以後IQ1を使っていない。低ビット量子化で回答品質がどう変わるか比較する。
- 追加②：Unslothモデルが最近更新され、**更新版UD-IQ3_XXSはすでにダウンロード済み**。旧版UD-IQ3_XXSと比較し、結果が変わるか確認する。
- 日本語論文要約では以前**量子化差よりseed差の方が大きく見えた**。要約側は同一入力・限定的な確認を優先し、小差の優劣を断定しない。
- 検索ではCOMMON-005 ROCm検証で**IQ3のみ誤答**と**IQ4のみ誤答**の双方が発生した。現状はIQ4の方が平均正解率が高そうだが、**データseedは2種類**、さらにROCmはtemperature=0・固定seedでもrun間の回答が変動するため、統計的優位は未証明。より難しい設問で差が現れるか／現れないかを評価する。詳細は[COMMON-005品質検証記録](R6-COMMON005-MH128K-QUALITY-PLAN-2026-11-03.md)。

## 2. 比較するモデル条件

| 区分 | モデル | 役割・注意 |
| --- | --- | --- |
| 主比較 | **旧Unsloth UD-IQ3_XXS（過去比較で使った重み）** | 過去の基準。PLE16等、実際のGGUF構成を照合 |
| 主比較 | **元Unsloth UD-IQ4_XS（過去比較で使った重み）** | IQ3との正解率差を検証する主対象。Huihuiとは別物 |
| 主比較 | **更新版Unsloth UD-IQ3_XXS（ダウンロード済み）** | 旧IQ3からの更新差を評価。量子化bit数は同じでもモデル版・量子化生成手順・テンソル差があり得る |
| 追加比較 | **旧Unsloth UD-IQ1_S（既存ローカルファイル）** | 低ビット量子化の影響を見る。まず現在のr6でロード・出力・tokenizer互換をsmoke |
| 参考・選択的 | ROCmFP4、Huihui、Gemma4 | 既存5モデルとの連続性確保。ただし**全seed×全設定の完走は必須にしない**。Gemma4は別モデル系列として解釈 |

旧5モデル比較に新IQ1・新IQ3の**2条件を追加**する意図であり、すべてを同じ量子化系列とみなさない。GGUFのSHA256、配布/revision、architecture、tokenizer、quantization、PLE16/分割形式、必要メモリを実行前に記録。特に旧IQ3対更新IQ3は**revision差**、旧IQ3対旧IQ4/IQ1は条件を揃えられた範囲での**量子化差**として分離する。

## 3. 論文要約：軽量な再確認

- 以前の日本語論文、プロンプト／採点観点を再利用できる範囲で固定する。旧5モデルの既存ログが残っていれば、無闇に全runを繰り返さない。
- IQ1、更新IQ3を中心に少数のseed/実行反復で、重大な事実誤認、抜け落ち、指示追従、情報粒度を確認。文体の差と内容の正誤を混同しない。
- 「量子化が強く影響しない」という仮説の検証ではなく、今回の追加2条件に**明瞭な品質差があるかのスクリーニング**とする。

## 4. 検索：新しい高難度セットを優先

1. 既存**MH-128Kの固定入力・正解・seed・スコアは改変しない**。新たにMH-Hard（仮称）を作る。先に回答キーと誤答分類を確定し、易しい問題での12/12天井効果を減らす。複数hop、近接リンク／別経路decoy、似た識別子、複数候補、長距離の照合などを候補にする。問題の実際の難易度はpilotで確認する。
2. **主比較は旧IQ3・旧IQ4・更新IQ3**。IQ1、ROCmFP4、Huihui、Gemma4は差が見えた設問・代表seedを中心に部分実施。限られた参考runを主比較の正解率ランキングに混ぜない。
3. データ生成seed（文書・設問内容）と推論sampler seed（乱数条件）を**別管理**。既存のデータseed2種類だけで結論を出さず、**独立した新データseedを複数**追加し、同一データ／同一設定の**ROCm複数run反復**も設ける。A/B質問順序は同じ設問の相関した反復であり、独立サンプルに数えない。
4. 同一比較群の入力データ、context、prompt、実トークン数、sampler、MTP、COMMON-005 Gather、backend、build、P-MODE/監視条件を揃える。原則ROCmを中心にしつつ、必要ならVulkanで決定性の参考確認。実行順序による環境の偏りを減らす。**モデルごとのtokenizer差やプロンプトtoken数を記録**し、完全一致しない場合はその制約を明記する。
5. 主指標は**厳密一致の正答率（独立データseed/問題単位）**、加えて誤答の種類、問題別の失敗再現頻度、run間の回答揺れ。反復run数とデータseed数を分けて集計し、**対応のある比較・不確実性**を示す。観測差が小さければ「差を検出できなかった」で止め、「同等」や「IQ4が統計的に有意に優越」とは言わない。検定・区間推定を行う場合は、先に主要比較・サンプル数・独立単位を決める。
6. この評価の主目的は**回答品質**。PP/TGの量子化別速度比較およびCOMMON-005のON/OFF性能/回帰ゲートとは分ける。

## 5. 再開時の順序と成果物
